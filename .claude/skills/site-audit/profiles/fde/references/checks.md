# Check catalogue

Generated from `<skill>/profiles/fde/data/checks.json` by `<skill>/scripts/render_checks.py --profile fde`. Edit the JSON, then re-run the script; do not edit this file by hand.

Last audit columns = results of the bundled baseline audit on 2026-10-09.

## Rules for IDs

- IDs are permanent. Never renumber or reuse one; history comparisons depend on them.
- A new check takes the next free number in its lens (e.g. `PQ-16`) and is added to `<skill>/profiles/fde/data/checks.json` first.
- A check that no longer applies stays in the catalogue and is recorded as `na` with a reason.

## Statuses

- `pass` — meets the pass condition everywhere it applies
- `partial` — meets it in some places or in part (counts as half in the pass rate)
- `fail` — does not meet it; evidence required
- `na` — does not apply yet (e.g. redirects before a restructure); excluded from the pass rate
- `not_checked` — skipped this audit; excluded from the pass rate and listed in the report

## Verify methods

- `scan` — crawl_inventory.py reports it (scan-checks.json)
- `read` — a person or subagent reads the pages
- `browser` — check in a real browser (references/browser-checks.md)
- `fetch` — fetch a specific URL and look at status or content
