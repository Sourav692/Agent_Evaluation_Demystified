End-to-end evaluation

Build one support assistant, then test every part of it: the search, the answers, the tool calls, the path each run takes, safety, the judges themselves, and the system after it ships.

14 lessons · about 3 hours of reading · Course 04 · Each page explains one notebook in plain language, with little code.

Part 1 · Build the system under test

The assistant every later lesson scores.

  1. 01The knowledge base and the RAG agent12 minBuild the half of the assistant that answers from help articles.
  2. 02Tools, agents and the supervisor13 minAdd actions, a router that picks who handles each message, and a record of every run.

Part 2 · The test set

Every score depends on it.

  1. 03The golden set14 minBuild 121 labelled test cases in six slices, then test the test set before trusting it.

Part 3 · Score each part

From the search step to the finished task.

  1. 04Retrieval evaluation15 minDid the search find the right passages? Labels against an LLM judge.
  2. 05Generation evaluation15 minGrade the answers, then split each failure between retriever, generator and test case.
  3. 06Tool call evaluation14 minRight tool, right arguments, and no call when none was needed.
  4. 07Trajectories and handoffs15 minGrade the path a run took and find the first step that failed.
  5. 08Task completion and conversations15 minCheck the store for ground truth, then test whole conversations.

Part 4 · Safety and judges

What must never happen, and when to trust a model's verdict.

  1. 09Safety and red teaming15 minWrite the policy, check every run, then attack the agent on purpose.
  2. 10Custom judges15 minRubric, decision-tree and pairwise judges for the store's own rules.
  3. 11Calibrating judges with human labels15 minMeasure agreement with people and decide which judges may gate a release.

Part 5 · Ship and keep watching

From a score to a release decision, and after release.

  1. 12Statistics, cost and experiments15 minError bars on every score, and comparing two versions case by case.
  2. 13The release gate and CI14 minFive fixed rules and one script that says ship or don't ship.
  3. 14Online evaluation and the loop14 minScore live traffic with no answer key and turn bad traces into new test cases.
