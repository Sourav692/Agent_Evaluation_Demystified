# Default weekly guide template

Use this structure for a full weekly guide. For other modes, keep only the sections required by `SKILL.md`. Replace placeholders with descriptive topic names and adjust the time estimate to the actual work.

Write explanations as short, connected paragraphs. Under theory, group related concepts into descriptive third-level topic headings. Define each new term before using it, explain the mechanism, and connect it to the worked example. The bullets below describe coverage, not a required bullet-only output format. Avoid repeating the same explanation across theory, the worked example, and the memory card.

# Week XX — [Precise topic]

**Difficulty:** Beginner / Intermediate / Advanced / Expert  
**Time:** 9 hours  
**Project state:** What the existing refund-agent example can do at the start.

## 1. Goal and prerequisites
- 3–5 measurable outcomes
- What the learner must already know
- What changes in the project this week

## 2. First, a real failure
- Customer request
- Agent behavior
- Why it matters
- What evidence we need

## 3. Theory, in plain English
- Definition and the core mental model
- Each key concept: plain-language meaning, purpose, mechanism, example, limits and failure checks
- Short ASCII or Mermaid diagram
- The right metric/check and where it can mislead

## 4. Worked example
- Small inputs and expected outcome
- Step-by-step evaluation trace
- Relevant trade-offs

## 5. Hands-on lab
- Prerequisites, exact file tree, setup and dependencies
- Full learning-friendly runnable code (mock by default)
- Commands and expected outputs (explicitly mark simulated)
- Positive / negative / adversarial scenarios
- How to interpret failed tests

## 6. Two debugging drills
- Broken input or change
- Symptoms and failed assertion
- Diagnosis steps
- Fix and verify

## 7. Staff-level design review
- 3–5 interview questions and concise model answers
- Architecture, constraints, trade-offs, observability, privacy, cost and failure recovery
- When *not* to use the chosen technique

## 8. Completion criteria
- Checkbox acceptance tests with concrete evidence
- One-page memory card: terms, rule of thumb, checklist
- Next week's prerequisite

## 9. Solutions / answer key
- Explain expected behavior without hand-waving
- Where useful, show exact test assertions
